  The problem

  ScoreRenderer's parameter order is (self, engine, config) — reversed from
  every sibling renderer and from the base, which are all (self, config, 
  engine). The orchestrator constructs renderers positionally:

  renderer = renderer_class(config, engine)   # orchestrator.py:40

  So for ScoreRenderer(self, engine, config), the positional binding is:
  - param engine ← the config dict
  - param config ← the Engine object

  Then your new super().__init__(config, engine) passes them as (Engine object, 
  config dict) → base stores self.config = <Engine> and self.engine = <dict>.
  Both swapped.

  Before this edit it was super().__init__(engine, config), which — with the
  reversed param names — accidentally cancelled out and stored them correctly.
  Your edit fixed the super() call to match the siblings but left the signature
  reversed, so now the double-swap is gone and the values land backwards. The
  type hints (engine: Engine, config: dict) now also actively lie about what
  each param receives at the call site.

  It doesn't crash today only because render() is pass and the base just stores
  the refs — but self.config/self.engine are wrong, and mypy would flag the call
  site once it runs.

  Fix

  Make the signature match the other renderers (and the call site):

  class ScoreRenderer(Renderer):
      def __init__(self, config: dict[str, Any], engine: Engine) -> None:
          super().__init__(config, engine)
